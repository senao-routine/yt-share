Fable 5.2 使い分けキット（Claude Code 用）

毎回 /model を切り替えて、気づくと Fable で全部回して週の枠が溶ける → /fable-plan <作りたいもの> の一言で、設計だけ Fable・作るのは Opus 5.5・探すのは Sonnet 5.5 に自動で分かれる（試験では Fable が書いた量が約5分の1・時間は半分以下・費用の目安は約3分の1）

非エンジニアの業務・開発者 向け
Fable52使い分けキット.zip をダウンロード

9 ファイル・7 KB。スマホで開いたときは、パソコンで開き直してからダウンロードしてください。

Claude Fable 5.2 は賢いけれど、単価は Opus 5.5 の2倍で、アプリでは週の利用枠の半分までしか使えません。 このキットを入れると、/fable-plan <作りたいもの> の一言で「設計だけ Fable 5.2・作るのは Opus 5.5・探すのは Sonnet 5.5」に自動で分かれます。 Fable の枠を、いちばん効く「設計」の分だけに使えます。

大きな仕事のたびに /model を切り替える。気づくと Fable で全部回して、週の枠がすぐ減る/fable-plan と打つだけ。設計書は Fable、実装と確認は Opus が受け持つ

試した結果（2026-11-10・議事録3本から週報を作る自動化を、同じ頼み方で作らせた）は「測った結果」の節にあります。

入れ方（3手）

  1. 入れる: bash install.sh ~/自分のフォルダ
  2. 「CLAUDE.md の追記.md」の中身を、そのフォルダの CLAUDE.md の末尾に貼る（無ければ新しく作る）
  3. そのフォルダで claude を起動 → /model opus → /fable-plan <作りたいもの>

必要なもの: Claude Code v2.1.321 以降（Fable 5.2 が使える版）と、Fable が使えるプラン（Max・Ultra・Team のプレミアム席、または usage credits）。

試し方（5分）

cp -R サンプル/minutes ~/自分のフォルダ/
cd ~/自分のフォルダ && claude
/model opus
/fable-plan minutes フォルダにある議事録（.md）から、やること・担当・期限を全部抜き出して、担当ごとにまとめた週報 weekly.html を作る Python スクリプト make_weekly.py を作って。標準ライブラリだけで。期限が近い順に並べ、期限切れは赤で。担当や期限が無い物も落とさない。

  • 差には「仕事を分けたこと」と「設計係の考える深さを high にしたこと」の両方が効いています。
  • 最初の版（設計係が xhigh・設計書の長さの上限なし）は、設計だけで13分・30KB を書き、Fable の量は17%しか減りませんでした。設計係を high にして設計書を120行以内にしたのが今の版です。
  • サブスクの枠の減り方は公開されていません。上の費用は「API で払ったらいくらか」の目安で、枠の減り方もおおむねこの比で変わると考えています（実測ではありません）。

気をつけること

  • Fable 5.2 は長い作業の途中で「続けますか」と止まることがあります。CLAUDE.md の追記.md の決まり（完成条件が通るまで続ける）で減らせます。
  • 短い質問・文の手直しは Opus 5.5 か Sonnet 5.5 で十分です（Fable は考えすぎて遅く高くなります）。
  • サブエージェントの model: は Claude Code の版によって書き方が変わることがあります。動かないときは claude update してください。

あなたは設計の担当です。実装は別の担当（メインのモデル）がします。あなたの仕事は、頼まれたことを実装できる設計書を1枚書くことだけです。

## 書くもの

作業フォルダの直下に `plan.md` を1つ書きます。**長さは 120 行以内**（実装する担当が5分で読める量）。中身は次の5つです。

1. **ゴール**: 何ができたら終わりか（1〜2文）
2. **完成条件**: 終わったことを確かめるコマンドや手順（実際に走らせて確かめられる形）
3. **作る物の一覧**: ファイル名と役割
4. **手順**: 1手順＝1ファイルくらいの大きさで、上から順に実装すれば終わる並び
5. **気をつけること**: 失敗しやすい所・入力の例外・やらないこと

## 進め方

- このフォルダのコードと資料は依頼者の持ち物です。設計に必要なら、今の構造を直す前提で書いてかまいません。
- 必要なファイルは自分で読んで確かめてから書きます。分からない値は「要確認」と書き、勝手に決めません。
- 設計書は最後まで書き切ってから返します。途中で「続けますか」と聞いて止まりません。
- コードは書きません（`plan.md` 以外のファイルを作らない）。
- 返事は「plan.md を書いた」と、手順の数と一番の注意点を3行以内で。

# /fable-plan — 設計は Fable 5.2、実装は今のモデル

頼まれたこと: $ARGUMENTS

次の順に進めてください。

1. **設計を Fable に頼む**: `fable-planner` サブエージェントに、上の頼まれたことの設計を頼み、`plan.md` を書かせる。
   既存のファイルを探す必要があれば、先に `sonnet-scout` サブエージェントで調べてから渡す。
2. **自分で実装する**: `plan.md` を読み、手順の上から順に、あなた（メインのモデル）が実装する。
   実装を Fable に頼まない（Fable の枠は設計の分だけにする）。
3. **確かめる**: `plan.md` の「完成条件」を実際に走らせ、結果をそのまま報告する。通らなければ直してからもう一度。
4. **報告**: できた物・確かめた結果・残った課題を5行以内で。途中で「続けますか」と聞いて止まらず、完成条件が通るまで進める。

## モデルの使い分け

| 役割 | モデル | 呼び方 |
|---|---|---|
| ふだんの作業・実装 | Claude Opus 5.5 | 起動したら `/model opus` |

install.sh

#!/bin/bash
# Fable 5.2 使い分けキット — 入れる先のフォルダへ .claude/agents と .claude/commands を写す。
# 使い方: bash install.sh <入れる先のフォルダ>
# 同じ名前のファイルが既にあるときは上書きせずに知らせる。
set -eu
here="$(cd "$(dirname "$0")" && pwd)"
dest="${1:-}"
if [ -z "$dest" ] || [ ! -d "$dest" ]; then
  echo "使い方: bash install.sh <入れる先のフォルダ>（フォルダが見つかりません: ${dest:-未指定}）" >&2
  exit 1
fi
mkdir -p "$dest/.claude/agents" "$dest/.claude/commands"
for f in agents/fable-planner.md agents/sonnet-scout.md commands/fable-plan.md; do
  if [ -e "$dest/.claude/$f" ]; then
    echo "そのまま: .claude/$f は既にあります（上書きしていません）"
  else
    cp "$here/.claude/$f" "$dest/.claude/$f"
    echo "入れた:   .claude/$f"
  fi
done
echo
echo "あと1手: 「CLAUDE.md の追記.md」の中身を、$dest/CLAUDE.md の末尾に貼ってください。"
echo "使い方: そのフォルダで claude を起動 → /model opus → /fable-plan <作りたいもの>"
