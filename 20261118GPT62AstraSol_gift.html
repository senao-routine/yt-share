ゲームの注文書キット

AI にゲームを頼むと「一言で頼む → 動かない・すぐ終わる・直す往復が続く」→ 一言のアイデアから、優先順位・数値・自己検証つきの注文書が 1 分でできて、できた HTML の自己検証もボタン 1 つで回せる（注文書を自分で書くと 30 分〜1 時間＝自分の検証ラボの作り込み版の注文書は 1 本 9〜14KB）

GPT-6.2 Astra／Sol の回（2026-11-18）のプレゼントです。 一言のゲームのアイデアを、AI が迷わない「作り込みの注文書」にして、1 枚の HTML でゲームを作らせ、できたゲームを自分で確かめます。

同じモデルでも、「ピンボールを作って」のような短い一言より、数値・優先順位・書く順序・自分で確かめる検査まで決めた注文書で頼むほうが、出来が大きく上がります。このキットは、その注文書を空欄を埋めるだけで作れるようにしたものです。

何ができるか

  • ① 注文書を作る: ジャンルの型（2D アクション／3D アクション・アスレチック／3D レース／ピンボール・物理のおもちゃ／シューティング／パズル／見下ろしの RPG／自由）を選び、名前・一言の説明・手本にしたい雰囲気・操作・勝ち負け・色とテーマ・入れたい物（3 つまで）・2D か 3D かを書き換える。注文書の全文がその場で組み上がり、コピーか 注文書.txt で保存できる。Codex で回す 1 行と、直すときの頼み方もコピーできる。
  • ② できたゲームを確かめる: できた HTML を落とす（選ぶ・本文を貼るでもよい）と、ゲームを切り離した枠の中で起動し、注文書に入れた自己検証 selfTest() を呼んで合格・不合格を 1 件ずつ出す。起動時のエラーの数・FPS・大きさ（KB）・仕様チェックリストの有無も出る。不合格は「直す頼み方をコピー」でそのまま AI に渡せる。「遊ぶ」で大きく開いて遊べる。
  • ③ 今回の検証の注文書: 動画の検証で実際に使った注文書の全文（ピンボール台・3D 鬼ごっこ・FPS アリーナ）と、GPT-6.2 Astra と Sol の使い分けの表。

2 つの使い方

画面で使う

キット.html をダブルクリックで開くだけ。インストールは要りません。入力した中身はどこにも送りません（ネットを使うのは、② で確かめるゲームが自分で外の部品を読むときだけ。3D のゲームは Three.js を読むので、ネットにつながっている時に確かめてください）。

ターミナルで使う（Claude Code・Codex）

ターミナルで使う/SKILL.md を、使う道具のスキルの置き場へ写します。

# Claude Code
mkdir -p ~/.claude/skills/game-order && cp "ターミナルで使う/SKILL.md" ~/.claude/skills/game-order/
# Codex
mkdir -p ~/.codex/skills/game-order && cp "ターミナルで使う/SKILL.md" ~/.codex/skills/game-order/

あとは作業用のフォルダで頼むだけです。

  • 「ピンボールの注文書を作って」→ 注文書.txt を作り、そのまま game.html まで作って selfTest() で確かめる
  • 「宇宙が舞台のシューティングを、注文書から作って」
  • 「パズルの注文書だけ作って」→ 注文書.txt で止まる

キットの ① で作った注文書を Codex に渡すなら、注文書.txt を置いたフォルダでこの 1 行（キットの画面からもコピーできます）:

codex exec --skip-git-repo-check --sandbox workspace-write -m gpt-6.2-sol -c model_reasoning_effort="high" "$(cat 注文書.txt) 完成した HTML は、このフォルダに game.html という名前で保存する。"

Astra にするなら -m gpt-6.2-astra。Codex が古いと新しいモデルが出てこないので、先に Codex を最新にしてください。

注文書が効く理由

  • 数値で固定する: 速さ・重力・ジャンプの高さ・当たりの大きさ・時間・個数・色を数字で書く。「適度に」「いい感じに」を使わない。
  • 優先順位と予算: 節ごとに P0（無いと遊べない）・P1（音と演出）・P2（上級）。足りなければ P2 → P1 の順に省き、省いた物は正直に書かせる。
  • 書く順序: 定数表 → 小道具 → 本体 → 採点 API → 起動、の順に書かせて、起動しない事故（定義より前の参照・同じ名前の二重定義）を防ぐ。
  • 自分で確かめる検査: window.__GAME の採点 API と selfTest()。「→ を押すと画面の右へ動く」と「FPS が 55 以上」は必ず入れる（左右が逆になる事故が多いため）。
  • 仕様チェックリスト: 最後に ✅／❌ で自己申告させる。嘘の ✅ は最も悪い、と先に書いておく。

気をつけること

  • 実在の作品名や商標を画面に出さない: 手本の雰囲気に実在のゲームの名前を書いても、注文書には「画面に出す名前はオリジナル」が必ず入ります。それでも、できたゲームのタイトル・キャラクター・ロゴ・音は自分の目と耳で確かめてください。人に見せる画面に注文書の雰囲気の欄が映るときは、作品の名前ではなく雰囲気の言葉で書くのがおすすめです。
  • 公開は自分の責任で: 作ったゲームを公開するかどうかは、使う人が決めてください。手本に似せすぎた見た目や音の作品は公開しないのが安全です。
  • 料金（サブスクの枠と API の従量）:
  • ChatGPT の Work や、ChatGPT のアカウントでログインした Codex は、契約しているプランの回数の枠の中で動きます（追加の料金はかからないが、枠を使い切ると待つ）。Astra は Sol より枠が少なく、Plus の目安は 5 時間に Astra 6〜50 回・Sol 17〜180 回です。
  • API キーで動かす使い方（API キーでログインした Codex や、自分のプログラムから API を呼ぶ）は、使った分だけ料金がかかります。100 万トークンあたり Sol は入力 $2・出力 $10、Astra は入力 $8・出力 $40（2026-11-18 の公式の料金ページ）。ゲーム 1 本で出力が数万トークンになることがあります。
  • ② の枠について: 読み込んだゲームは、キットのページから切り離した枠の中で動きます（ゲームからキットの中身には触れません）。ただしゲーム自身は外の部品を読みに行けるので、知らない人から貰った HTML は、開く前に中身を確かめてください。
  • 画面の無いブラウザでの確認: ターミナルのスキルで自動で確かめると、描画が遅くて FPS の項目だけ落ちることがあります。そのときはキットの ② で確かめ直してください。
