結論 — 何を返すAIなのか

一文で言い切る：Jev AI は、文章を書かないAI。返ってくるのは、型の決まった判定と、その確信度だけ。

実物のレスポンス

{
  "answers": { "is_urgent": { "noul": 0.92 } },
  "usage": { "cost": 0.00001533 }
}
これで全部です。文章がどこにも無い。「緊急です」とも「0.92です」とも書かれていない。 0.92 という数字が、そのまま返ってくる。だからプログラムがそのまま使えます。

いちばん伝わる言い換え（X で66万表示）

「gpt や claude を置き換えるものじゃない。ただの"本当に"賢い switch 文だ」

→「2016年の分類器が、2026年の賢さを手に入れた。そういう道具です」

AIに何かを"判定"させている人は、全員関係あります。メールの仕分け、問い合わせの振り分け、 コメントの選別、コードのチェック——あれ、全部LLMにやらせる必要なかったんです。

作ったのは TypeSafe AI ／ Diogo Almeida（InstructGPT・RLHF の共同発明者）。 本人の言葉＝「ChatGPTを共同発明したあと、なぜ超人的なチャットモデルがAGIにつながらないのかをずっと自問していた」

Jev とは何か

① そもそも何が新しいのか

System One モデル＝人間の思考でいう直感の側だけを担当するAI。文章生成の口をそもそも持っていない。 入力＝状態（判定したい文章）＋型のついた質問／出力＝判定＋較正済みの確率。

AIに作文させるのをやめて、決裁だけさせる。

質問の型は3つだけ

型返すもの例
Noulはい／いいえを 0〜1の確率でこの問い合わせは緊急か → 0.92
Choice決めた選択肢から1つ＋各選択肢の確率＋確信度カテゴリ → 不具合・障害／確信度 0.97
Score段階評価（小数で返る）不満度 0〜4 → 3.07
選択肢は呼ぶ側が先に決める。だから、定義にない答えは返ってこない。 これが「ハルシネーションしない」と言われる仕組みの正体（＝出力形式の話）。
返ってくるのは「型のついた判定」と「確信度」だけ。文章は一切返ってこない。

② よくある3つの疑問

ChatGPTの代わりになるの？なりません。文章が書けない。要約も翻訳も執筆も無理
精度が上がるの？上がりません。うちの検証では簡単な分類ならLLMも同じく正解した。差がつくのは速度と費用だけ
難しそうcurl 1本で動きます。登録して、キーを入れるだけ

③ なぜ速いのか＝この回の核心

公称は 70〜500ms・LLM比40〜200倍。うちの回線では、1問だけなら十数倍。でも質問を増やすと話が変わる。

条件JevClaude Opus 5差
規約24項目のチェック332ms18,966ms57.1倍速・411倍安
同じ課題を1項目に282ms3,888ms13.8倍
伸び率（1問→24問）1.18倍4.88倍—
LLMは答えを"文字として書く"から、項目が増えるほど時間が伸びる。Jevは全部を同時に返すから伸びない。
一言で：速いんじゃなくて、"増えない"んです。
公称の40〜200倍は条件つきで本当でした。束ねるほど公称に近づく。
チェック項目を1→20に増やしても応答時間は 315ms → 312ms。増えるのは費用だけ（2026-09-22 実測）。

④ 料金と制約

$0.042 / 100万入力トークン・出力は $0。コンテキストは 32,000トークン。24項目の監査1回で約0.011円。 比較：Claude Opus 5 は入力$5.00・出力$25.00（100万トークンあたり）。

今日このあと動かすアプリ、全部合わせても1円行きません。

⑤ なぜ今か＝時事フック

  • 9月15日 早期アクセス開始 → 申し込み殺到でAPIが一時停止
  • 9月21日 waitlist 撤廃。誰でも登録するだけ・$5クレジット付き（約1.2億トークン）
  • そしてもう追随が出ている：Laya（オープンウェイトの System One）が「ローカルで Jev の11〜50倍速」という報告。16GBのMacBook Airで動くという
これはツール1個の話じゃなくて、"System One"という新しい型の1号機。だからもう2号機、3号機が出てきている。
⚠ Laya は自分で検証していない。必ず「そういう報告がある」と言う。

⑥ 今日から始める手順

  • 公式：console.typesafe.ai で登録するだけ。$5クレジット付き
  • 他の経路：OpenRouter（typesafe/jev-1.13）／Cloudflare Workers AI／Vercel AI Gateway
⚠ 叩き方が普通のAPIと違う：chat/completions では400。POST /api/alpha/decisions を使う。
curl -s -X POST "https://openrouter.ai/api/alpha/decisions" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "typesafe/jev-1.13",
    "state": "払い出しが3日間ずっと失敗しています。至急なんとかしてください。",
    "questions": {
      "is_urgent": {
        "type": "noul",
        "instructions": "この問い合わせは緊急対応が必要ですか？",
        "criteria": {
          "true":  "業務が止まっている・金銭的被害・期限が迫っている",
          "false": "すぐ対応しなくても実害が出ない"
        }
      }
    }
  }'

どこに使えるのか

効く仕事の4類型

型具体例デモ
大量の文章を仕分ける問い合わせ・メール・コメント・応募書類①
1つの対象を多くの観点で見る台本・規約・契約書・コードレビュー②
道具を選ぶ・振り分けるどのツールを使うか・どのモデルに回すか③
件数の多い数値判定献立のカロリー・帯分け・注意フラグを1ヶ月ぶん（写真を読むのは別のAIの仕事）④
共通点は、答えが"言葉"じゃなくて"どれか"や"何点"で済む仕事。そこだけ効きます。

ネットで注目されている設計

  • 3層に分ける考え方：内側＝正規表現などのコード／中間＝Jevの確率つき判定／外側＝LLMの文章生成 →「今までは内側か外側しかなかった。その真ん中が空いていた」
  • ハーネスに検査層を"足す"：置き換えではなく、これまで高すぎて検査を置けなかった所に置ける （入口チェック／検索結果フィルタ／ループ検出／出力検証／メモリ照合）
  • 伸びている紹介：Jev×Codex の実践ガイド（45万表示）／活用術15選（17万表示）／browser-use の jev-ultrafast
真ん中の層が空いていた。確信度がしきい値を下回った件は、自動で人に回る。

向いていない仕事（正直に言う・信頼の担保）

  • 文章が欲しい仕事には一切使えない（要約・翻訳・執筆）
  • 簡単な分類では差がつかなかった：40業種分類は Jev も LLM も正解。精度差は出ていない
  • 「ハルシネーションしない」は出力形式の話。判断の中身が正しい保証ではない
  • 確率が0.5付近のときどうするかは、使う側が決める（→デモ①③で実演）

実際に動かした4つ

デモ①｜危険なコマンドの門番（/sort）

「判定だけのAI」が何の役に立つかを、説明なしで分からせる。

  1. http://localhost:8777/sort を開く
  2. 題材タブ「危険なコマンドの門番」を選ぶ
  3. 「仕分けを流す」→ 25本のコマンドが3つの箱に落ちていく
  4. rm -rf /・fork爆弾・curl|bash が「実行しない」に入るのを指す

確信度1.00で止まる。「AIにコマンドを任せる時代に、入口に門番を置ける」

確信度が低く、自動で人に回った件

コマンド確信度
git push --force origin main0.76
git reset --hard && git clean -fdx0.34
npm install express0.71
force push は「実行しない」と判定されませんでした。でも確信度が0.76で、しきい値0.80に届かなかったから、自動で人に回った。 迷ったら人に聞く、が既定になっている。これが確信度が返ってくる意味です。

モデル時間費用

デモ②｜一斉点検（/check）なぜ速いのかの証明

「速いんじゃなくて増えない」を、目の前で証明する。

  1. http://localhost:8777/check を開く
  2. 「良い例を入れる」→「点検する」→ 20項目が一瞬で全部立つ
  3. 項目数を 1 にして点検 → 5 → 20
  4. 左下に積み上がった実測表を指す
項目数応答時間費用
1項目315ms$0.0000186
5項目442ms$0.0000279
20項目312ms$0.0000627
20倍にしたのに、時間が変わっていません。費用だけ3倍。 LLMなら20倍の時間がかかります。ここがこのモデルの正体です。

「よくある例を入れる」（＝「どうも、こんにちは。まずチャンネル登録を…」） → 「挨拶で始まっていない」0.04・「具体的な数字が入っている」0.04 で落ちる

自分の台本、これで毎回点検してます。

デモ③｜スキル・ルーター（/route）どこに使うかの答え

LLMのFunction Calling（ツール選択）は、文章を書かせなくていいことを見せる。

  1. http://localhost:8777/route を開く
  2. 「サムネイルを作りたい」と打つ → 打ち終わる頃には答えが出ている
  3. 候補の確率バーを指す
  4. 「ショート動画を3本作りたい」と打つ
入力選ばれたスキル確信度時間
サムネイルを作りたい/youtube-thumbnail1.00316ms
ショート動画を3本作りたい/edit-short 0.78 ／ /short-video 0.210.76—
うちのスキルに、似たものが2本あることをAIが見つけました。これ、普通に使ってたら気づかない。 確信度が低いこと自体が情報になっている。

ふつうは「どのツールを使うか」をLLMに文章で答えさせます。でも選ぶだけなら文章は要らない。 だから59択でも0.3秒・0.03円です。

デモ④｜30食のカロリー判定（/meal）件数を積むと差が体感になる

1件なら体感できない速さの差を、1ヶ月ぶん30食を捌き切る合計時間で比べる。返させるのは推定カロリー・カロリー帯・食べ過ぎ注意の3つだけ。

  1. http://localhost:8777/meal を開く
  2. モデルを3つ（Jev／Claude Opus 5／Gemini 3.8 Flash）選び、30食のまま「分析する」
  3. 30食を捌き切るまでの合計時間と、カロリー帯への仕分けを見比べる
モデル30食の合計1食あたり費用1ヶ月の合計
Jev10.3秒0.35秒$0.0009427,495 kcal
Gemini 3.8 Flash127.6秒4.0秒$0.049722,440 kcal
Claude Opus 5199.8秒6.2秒$0.16121,860 kcal

2026-09-24・自宅回線・OpenRouter 経由・3モデル同時発走・温度0の1回測定。回線で変動します。

1食だと差は一瞬。でも30食積むと、この差になります。

ただしJev だけ合計を高めに出しました（参考値22,600 kcalの約1.2倍）。参考値は目安で正解ではありませんが、 速さと費用は判定モデル、数値の細かさはLLMに分がある、というのが正直なところです。

写真を渡すとどうなるか

渡したものJev の答え（「赤色ですか？」）入力トークン
赤い画像0.45493
青い画像0.45（同じ）496
文章で「真っ赤な画像です」0.96320
文章で「真っ青な画像です」0.01320
Jev は画像を読めません。渡してもエラーにならず（HTTP 200）、画像を文字列として受け取って「分からない」と答えます。 だから写真を読む係と、判定する係は別。写真から献立の文章にするのはマルチモーダルのAIの仕事で、 そこから先の「30食ぶんを仕分けて数える」が判定モデルの土俵です。

（デモの合間に30秒）最初に必ず踏むエラー

  1. choice の criteria は辞書／score の criteria は配列。逆にすると 400
  2. score は整数で返らない（3.07のような加重平均）
  3. 32,000トークン上限
  4. OpenRouterのモデル一覧に Jev は出てこない（alpha専用）。chat/completions では400
criteriaの型で30分溶かしました。

まとめ

  1. Jev AI は文章を書かない。型のついた判定と確信度だけを返す
  2. 速さの正体は「判定をいくつ増やしても時間が増えない」こと
  3. 使いどころはLLMの代わりではなく、LLMの前・横に足す所
使うべき人仕分け・採点・振り分けを大量に回している人
使わなくていい人AIに文章を書かせたい人（そこは今まで通りLLM）
今日3回、確信度が低いから人に回す場面が出ました。 AIが「分からない」と言えるようになった、というのがこのモデルのいちばん大きい変化だと思います。
