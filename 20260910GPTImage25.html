GPT Image 2.5 を実測する
「API料金2倍」は誤報だった

Routine Labo ／ 画像生成AI

2026年9月8日、OpenAI が ChatGPT Images 2.5 を公開しました。同時に API へ gpt-image-2.5-flare と gpt-image-2.5-sunburst の2モデルが追加されています。 公開直後から「API の料金が2倍になった」という情報が流れましたが、公式の価格表を開いて確かめたところ、 単価は1円も変わっていませんでした。このページでは、その誤解がどこから生まれたのかを一次情報で示し、あわせて仕様と提供状況をまとめます。

1. 何が出たのか

  • リリース：2026年9月8日（モデルの snapshot も 2026-09-08）
  • API のモデルは2本立て：Flare（速くて高品質な日常用）と Sunburst（編集精度が最優先の用途）
  • 提供先は ChatGPT の全ティア・Codex・API の3か所
  • 公式の主張：Images 2.0 比で最大50%高速、参照写真の被写体保持が向上、複数ターン編集の指示追従が向上
  • これまでの累計生成枚数は 30億枚（ChatGPT Images と GPT-Image API の合計）

2. 「料金2倍」はどこから来たのか

先に結論です。公式の価格表で、GPT Image 2 と GPT Image 2.5 の単価は同額です。 モデルカードにも、そのものずばりの一文が書かれています。

OFFICIAL — モデルカードの原文

“Token rates match GPT Image 2. The GPT Image 2 calculator does not estimate GPT Image 2.5 token consumption.”

前半で「単価は GPT Image 2 と一致する」と明言し、後半で「2 の計算機では 2.5 のトークン消費量は見積もれない」と続けています。 つまり単価は据え置き、ただし消費量は別物という、2つの異なることを1文で言っています。ここが今回いちばん大事な区別です。

では「2倍」という話はどこから出たのか。同じページの中に、バッチ料金の表があります。 Batch API は通常の半額で、そこに GPT Image 2 が image 出力 $15.00 で載っています。 この $15 と、2.5 の通常価格 $30 を並べると、ちょうど2倍に見えます。比べている列が違うわけです。

モデル種別通常価格（100万トークンあたり）バッチ料金
gpt-image-2image 出力$30.00$15.00
gpt-image-2.5-flareimage 出力$30.00—
gpt-image-2.5-sunburstimage 出力$30.00—
いずれもtext 入力$5.00$2.50（2のみ）
いずれもimage 入力$8.00$4.00（2のみ）

出典：OpenAI API Pricing（2026-09-09 取得・Standard / Batch 両方の表をDOMから実測）｜developers.openai.com
※ 現在の Standard 表に載っているのは 2.5 の2モデルで、gpt-image-2 の行は旧モデル側へ移っています。 2 の標準価格が $30 である根拠は、モデルカードの「Token rates match GPT Image 2」と、 Batch 表の $15（Batch は標準の半額）の2点です。

ただし「請求が同じ」とは言っていません。 品質設定に xhigh と max が新設され、従来の上限だった high の上に2段増えました。 上の品質を選べば1枚あたりの消費トークンは当然増えます。単価と請求は別の話です。

4. どこで使えるのか、いつから使えるのか

ChatGPT では全ティアに提供されるので、無料枠でも触れます。 ただし 提供は順次で、アカウントによって届く時期に差があります。実際、2026-09-09 の時点で、 私の Codex 枠にはまだ 2.5 が来ていませんでした。

日時（JST）やったこと結果
2026-09-09 20:54Codex で1枚生成して来歴情報を判定gpt-image 2.0
2026-09-09 20:57同じ手順で再確認gpt-image 2.0
2026-09-09 21:21図解を1枚生成（この図）gpt-image 2.0
2026-09-09 21:01codex --version と npm の最新版を照合どちらも 0.153.4（＝最新）

CLI は最新版なので、更新しても解決しません。切り替える設定も存在せず、届いたら自動的に変わります。 確かめ方は、生成された画像に埋め込まれた来歴情報（C2PA）を読むことです。 モデルの自己申告ではなく、成果物から確認するのが確実です。

bash ~/.claude/scripts/image_model_probe.sh --generate

5. Flare と Sunburst の使い分け

FlareSunburst
公式の位置づけ速くて高品質な日常用編集の精度が最優先の用途
向く場面大量に作る、素早く試す広告ビジュアル、最終仕上げ
トークン単価同じ同じ

単価が同じなので、選ぶ基準は価格ではなく「時間をとるか、精度をとるか」になります。

使える設定

  • 品質：low / medium / high / xhigh / max / auto（xhigh と max が新設）
  • サイズ：1024×1024 / 1536×1024 / 1024×1536 が推奨。カスタムは16の倍数、比率は1:3〜3:1、最大辺3840px
  • 出力形式：PNG（既定）/ JPEG / WebP、透過背景に対応
  • 使える API：画像生成（v1/images/generations）と画像編集（v1/images/edits）
  • その他：ストリーミング（partial_images 0〜3）、action で生成と編集の強制、moderation の緩和

6. 弱点も見ておく

公式自身が、次の3つをまだ課題として残っていると書いています。

  • テキストの正確な配置と鮮明さ
  • 同じキャラクターやブランド要素を、複数回の生成にわたって保つこと
  • 複雑なプロンプトは最大2分かかることがある

部分編集についても、頼んでいない箇所まで書き換わることがあります。「指定した領域の外側が何パーセント変化したか」は数値で測れるので、今後そこを検証していきます。
