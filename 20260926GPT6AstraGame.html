大乱闘風・サバイバー風・3Dアクションの3本を、デザイン画から3D化、ゲーム本体、仕上げまで再現できるように、使ったプロンプトと手順をそのまま載せました。コピーして Codex アプリに貼って使えます。

準備

はじめに用意するもの

  • Codex アプリ（GPT-6 Astra を選択）。ブラウザ操作は対話画面で動きます
  • Tripo のアカウント。Web版と API（CLI）はクレジットが別です。CLI を使うなら API 用を別にチャージします
  • Node.js 20 以上（tripo CLI 用）と Python 3（ローカル配信とモーションの修正用）
  • 画像生成が使える環境（Codex アプリの画像生成など）

3本それぞれ、デザイン画 → 3D化（Tripo）→ ゲーム本体（Astra）→ 遊んで直すの順に進めます。ゲーム1本あたり、キャラと小物で 1,000〜1,600 クレジットほど使いました（Smart Mesh P2.0 は画像から1体 110）。

全体の流れ

6つの手順で、ゲームが1本できる

  1. 1
    デザイン画を描く
    ゲームごとに画風を変える（格闘＝かっこいい・ホラー＝暗く・3Dアクション＝原色のマスコット）
  2. 2
    ブラウザで Tripo を操作して1体作る
    Codex アプリが Web版を操作して、生成から保存まで
  3. 3
    CLI でまとめて3D化する
    Smart Mesh P2.0 → 骨入れ → モーション → 腰の前進を取り除く
  4. 4
    ゲームを作る
    原作ジャンルの世界観・操作・カメラを数値で指定して依頼する
  5. 5
    遊んで確かめる
    引き戻し・姿勢・カメラ・難易度を確認させて、直させる
  6. 6
    何周か直す
    1周で完成しない。見えた問題を具体的な数値で返す

手順3の道具

腰の前進を取り除くスクリプト

strip_root_motion.py として保存して使います

#!/usr/bin/env python3
"""Tripo のモーション glb から、腰（Hip）の「1周で進む分」を取り除く（その場で動く形式にする）。
使い方: python3 strip_root_motion.py assets/*/anim_*.glb
Tripo v1.0 の骨は Z が高さ。水平2軸だけを直し、上下の揺れは残す。"""
import json, struct, sys, array
for p in sys.argv[1:]:
    b = bytearray(open(p, 'rb').read())
    L = struct.unpack('<I', b[12:16])[0]; j = json.loads(b[20:20 + L]); bo = 20 + L + 8
    changed = False
    for anim in j.get('animations', []):
        for ch in anim['channels']:
            node = (j['nodes'][ch['target']['node']].get('name') or '').lower()
            if ch['target']['path'] != 'translation' or node not in ('hip', 'hips', 'pelvis'):
                continue
            a = j['accessors'][anim['samplers'][ch['sampler']]['output']]
            bv = j['bufferViews'][a['bufferView']]
            off = bo + bv.get('byteOffset', 0) + a.get('byteOffset', 0); n = a['count']
            v = array.array('f'); v.frombytes(bytes(b[off:off + n * 12]))
            for k in (0, 1):  # 水平2軸
                d = v[(n - 1) * 3 + k] - v[k]
                for i in range(n):
                    v[i * 3 + k] -= d * (i / (n - 1) if n > 1 else 0)
                vals = [v[i * 3 + k] for i in range(n)]; r = max(vals) - min(vals)
                if r > 0.35:  # 前へ流れ続ける分は平均へ寄せる
                    m = sum(vals) / n
                    for i in range(n):
                        v[i * 3 + k] = m + (v[i * 3 + k] - m) * 0.35 / r
            b[off:off + n * 12] = v.tobytes(); changed = True
    if changed:
        open(p, 'wb').write(bytes(b)); print('fixed', p)

手順4　ゲームを作る

assets/ を置いたフォルダで使います

Three.js で、4人対戦の格闘アクション「天空闘技場」を、対戦アクションの原作ジャンルらしさで作ってください。

## キャスト（4〜5頭身のかっこいいヒーロー）
- valk（蒼剣の騎士）：必殺＝剣から蒼い三日月の衝撃波
- riza（空賊の二丁拳銃）：必殺＝連射と跳び退き射撃（射撃は fire のモーション）
- garou（狼の拳闘士）：必殺＝突進アッパー（残像と地面の亀裂）
- mira（雷と氷の魔導士）：必殺＝落雷の範囲と氷の柱
- 無い動き（空中攻撃・ガード・崖つかまり）は、手持ちのクリップの切り出し・速度・体の傾きで

## 原作らしさの芯
- キャラ選択（大きな立ち絵と名前）→ 降り立つ登場演出 →「3・2・1・GO!」→ 試合 →「GAME SET」→ 勝利ポーズと順位
- 弱（連打）・強（溜めで大きく吹っ飛ぶ）・空中攻撃・必殺・ガード・回避・崖つかまり。ダメージ％は大きく太い数字
- 吹っ飛びは煙の軌跡、撃墜は画面端で光の柱と星。アイテムが空から落ちる
- ステージ：古代の天空闘技場（彫刻の石に金の象嵌・側面は岩と光る結晶・両端に旗と炎）＋左右と上のすり抜け床
- 背景：藍→紫→燃える橙の空、何層もの雲海が視差で流れる、遠くの城や塔のシルエット、浮かぶ岩のかけら
- トレーニングモード（CPU が立ったまま・ダメージ％リセット）

## 操作の手触り
- 押した次のフレームで反応。地上の加速 0.08 秒で最高速、止まるのは 0.1 秒。空中の左右は地上の7割
- 短押しで小ジャンプ・長押しで大ジャンプ。先行入力 0.1 秒、足場の端から 0.08 秒以内ならジャンプ可。重力は重め、空中ジャンプは1回
- 攻撃は入力から 2〜4 フレームで発生。CPU は地上と足場での攻防を優先し、開始3秒以内に全員が戦い始める

## カメラ
- 横から見る型（見下ろし 10 度前後）。全員を常に画面に収めて上下左右にパン＆ズーム、同時にメインステージの上面は画面の下半分に残す
- 全員が近いときはファイターが画面の高さの1/7〜1/6。画面外のファイターは縁に矢印と顔アイコン

## 共通の前提
- 世界観・遊び方・カメラ・色・ステージ構成・手触りは原作ジャンルに限界まで寄せる。キャラクター本人・名前・ロゴ・実在のステージ・固有の効果音やBGMはオリジナルにする

手順5の道具

ローカル配信スクリプト

serve.py として保存して使います

#!/usr/bin/env python3
"""ゲーム確認用のローカル配信。標準の http.server は待ち行列が小さく、glb を並列に読むと接続を切ることがある。
使い方: python3 serve.py [port]"""
import sys, http.server, socketserver
class S(socketserver.ThreadingMixIn, http.server.HTTPServer):
    daemon_threads = True; request_queue_size = 256; allow_reuse_address = True
class H(http.server.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cache-Control', 'no-store'); super().end_headers()
S(('127.0.0.1', int(sys.argv[1]) if len(sys.argv) > 1 else 8000), H).serve_forever()
つまずきやすい所

実際にやって分かった落とし穴

症状原因と対処
移動中にキャラが元の位置へ引き戻される／移動が速すぎる--animate-in-place を指定しても、走り・歩きに腰の前進が残る（1周で1〜3）。手順3のスクリプトで取り除く
空中でキャラが倒れ込むプリセットの fall は「転んで倒れ込む」動き。空中は jump の後半を使う
射撃で体が大きく倒れ込むプリセットの shoot は伏せ撃ち。立ち撃ちは fire
モーションを付けると失敗するCLI 既定の骨（v2.5系）に人型モーションが載らない。骨入れで -p model=v1.0-20240301
モーションを何本も頼んだのに1本しか入っていないまとめて指定すると最後の1本だけ。1本ずつ付ける
キャラが代わりの形で表示される標準の http.server は同時接続に弱く、glb の読み込みを切る。手順5の serve.py を使う
地面が描かれない（シェーダーのエラー）シェーダーの自作関数名が three.js 内部の名前（reflectedLight など）と重なった。自作名には接頭辞を付ける
カメラが近すぎる・見上げる・物で埋まる「いい感じに」ではなく、画面上のキャラの大きさ・見下ろし角・高さの上限を数値で指定する
